# TermHub 自管加密凭据库设计

日期：2026-09-25

## 目标与边界

TermHub GUI、MCP 和 Smoke 不再对 macOS 钥匙串中的 SSH 密码或私钥口令执行读写、探测或删除。GUI 使用用户设置的 TermHub 主密码解锁自管加密库。MCP 不接收、记录或持久化主密码；只有 GUI 运行且已解锁时，MCP 才能新建需要凭据的连接。旧钥匙串条目保留原状，不自动迁移，也不作为新库的回退来源；用户在 GUI 中重新录入每台主机的凭据。

## 加密库

- `CredentialVault`（TermHubCore）持有唯一的进程内解密密钥和加密文件操作。首次启动创建主密码；再次启动必须输入主密码。显式锁定或退出即丢弃进程内密钥。忘记主密码无法恢复密文，只能明确确认重置新库并重录凭据；重置不得碰旧钥匙串。
- 在 `~/Library/Application Support/TermHub/` 保存独立、版本化的加密文件。用随机盐和 PBKDF2-HMAC-SHA256（不少于 600,000 轮）从主密码派生 AES-256-GCM 密钥；随机 nonce、认证标签和格式版本存文件中。整个 `{host UUID, password/passphrase}` 映射为密文，不在 SwiftData、偏好设置或日志写入明文、主密码、派生密钥。错误密码和损坏文件都不能被当作空库覆盖。
- 首次写入使用排它创建，后续写入采用同目录临时文件、同步及原子替换，并对文件设 `0600`、目录设 `0700`；失败保持上一份完整密文。加密算法、轮数和格式版本可读取用于将来升级，但不静默降级。文件权限是同一登录用户之外的保护；不能声称抵御已经控制该用户进程的恶意软件。
- 读 API 区分 `locked`、`missing`、`corrupt`，不能用 `nil` 混淆。保存/删除要求已解锁；主机删除时清理新库中的该主机条目。主密码变更要用当前主密码重新验证，再以新盐/密钥原子重加密，失败不破坏旧库。

## GUI 与连接行为

- 应用入口先展示“创建主密码/解锁”界面；只有成功解锁才显示主机与连接界面。主密码输入只在 UI 与内存中存在，不进命令行参数、环境变量或日志。设置里提供显式锁定、更改主密码；锁定立即关闭活动 SSH 会话，清空新建连接的权限。
- 主机编辑页保存密码和私钥口令到加密库；密码存在标记来自解锁后的库状态，不在 SwiftUI 的 `body` 中解密。侧栏、详情、测试连接、跳板链、自动重连和资源采样共同使用一个凭据提供接口；锁定返回明确错误、不触发弹窗循环。输入临时凭据的测试连接只用当前表单值，不隐式写库。
- 旧钥匙串主机在新库里显示“需重新填写密码”，绝不自动读取旧条目。未加密的主机配置和 `known_hosts` 保持原语义，密钥路径认证的无口令私钥仍可正常使用。

## MCP 与工具

- GUI 在解锁期间提供用户专属的本机 Unix domain socket 凭据服务，socket 权限 `0600`，校验对端有效 UID；锁定或退出时关闭监听、清除 socket。只按已保存主机 UUID 和 `password/passphrase` 返回单条凭据，严格限长，不提供批量导出或主密码接口。MCP 客户端请求有超时，不把凭据写入 MCP 响应、调试日志或持久文件。该通道信任同一 macOS 用户下的进程，不把 UID 检查误称为对同用户恶意进程的强隔离。
- MCP 的 `list_hosts` 不需要解锁；`exec`、容器、资源等需要建连的工具在 GUI 未运行/未解锁时返回明确的解锁指引，不访问旧钥匙串。锁定后不得复用 MCP 连接池中的旧连接；新请求先查询解锁状态，清理旧连接。GUI 已解锁时保留现有主机指纹校验与跳板认证。
- 移除 MCP `--set-password <别名> <密码>` 命令行入口，改为在 GUI 内录入。Smoke 的持久化导入/审计路径改用新库或测试夹具，不调用钥匙串；仅使用临时表单/标准输入密码的无持久化测试仍可用。
- 本地构建/更新流程默认不扫描登录钥匙串寻找代码签名身份；采用不访问钥匙串的签名路径。若发布者主动提供外部签名身份，则作为单独的显式发布操作，不在普通启动、构建或更新时索要 Mac 密码。

## 验证与交付

- 单元测试：创建、错误主密码、重启后解密、AES-GCM 篡改检测、保存/覆盖/删除、原子写失败保留旧数据、主密码变更、锁定后禁止读取；使用临时目录及非真实凭据。
- 集成测试：GUI 解锁/锁定与密码缺失提示、SSH 密码及私钥口令路径、跳板链、MCP 已解锁/锁定/GUI 退出三态、MCP 连接池失效、socket 权限、构建脚本不再调用钥匙串。测试不得读取真实钥匙串或把真实密码作为测试数据。
- 验收：全代码路径中不存在 `SecItem*`/旧 `KeychainStore` 调用；新建、更新、重新启动、锁定及 MCP 调用不会再弹钥匙串授权框；旧条目保留，用户重录的新密码只存在于密文文件和短暂进程内存。区分代码测试与运行中 App/MCP 的实际二进制验证。

## 不做

不在本次删除旧钥匙串数据，不静默迁移旧密码，不把主密码放入 MCP 工具参数/进程参数/环境变量，也不实现 TermHub 退出后可独立解锁的常驻守护进程。
